# Mineradio 跨平台移植工作量清单

> 基于对源码的静态扫描（2026-11-06，版本 2.2.0）。
> 结论先行：**核心播放体验可低成本移植；"桌面融合"类招牌功能是纯 Windows 实现，mac 上要么重做要么砍掉。**

## 总览

| 层级 | 内容 | 移植难度 |
|---|---|---|
| A | 可直接跨平台的核心 | 低 |
| B | 有平台判断、需补 mac 分支 | 中 |
| C | Windows 专属，需重做或裁剪 | 高 |
| D | 打包与分发链路 | 中 |

---

## A. 跨平台核心（基本不用动）

- **本地服务 `server.js`**：网易云/QQ/酷狗/Spotify 接口、代理、登录态，纯 Node，跨平台 ✅
- **音频解密 `qishui-audio-decryptor/`**：纯 JS 实现（mp4-box / track-decryptor），**无 Windows 二进制** ✅（此前担心是误判）
- **`qishui-auth-v6/`**：纯 JS + HTML，跨平台 ✅
- **前端界面 `public/`**：HTML/CSS/JS，GSAP、粒子视觉、歌词舞台 ✅
- **`dj-analyzer.js`、`music-metadata`、`mpg123-decoder`、`gsap`**：跨平台依赖 ✅

## B. 有平台判断，需要补 mac 分支

| 位置 | 现状 | 工作量 |
|---|---|---|
| `desktop/main.js`（5972 行的大文件） | 约 8 处 `process.platform === 'win32'` 守卫；darwin 退出行为已有（`:5972`） | 补 mac 路径：托盘、菜单、开机自启方式 |
| `desktop/local-music-library.js:70` | 路径大小写折叠仅 win32；mac 默认文件系统不区分大小写，逻辑可直接套用 darwin 分支 | 半天 |
| `desktop/app-memory.js` | 非 win32 直接返回 unsupported，已是安全降级 | 无需改，mac 上功能自然关闭 |
| `desktop/system-memory.js` | 同上，安全降级 | 无需改 |
| 更新机制 | 走 GitHub Releases + 浏览器打开，跨平台 ✅（但注意 fork 后要改 owner/repo 指向） | 改配置即可 |

## C. Windows 专属功能（移植决策点）

### C1. Wallpaper Engine 壁纸接入 — 建议：mac 上砍掉
- `wallpaper-engine-library.js`：扫描 Steam `libraryfolders.vdf`、`steamapps/workshop/content/431960`、`wallpaper32/64.exe` 进程管理（PowerShell）
- `wallpaper-engine-runtime.js`：~1600+ 行，spawn `wallpaper32/64`、命名管道、DWM 表面、指针中继——整套是和 Windows 版 WE 的进程协议对接
- **mac 上 Wallpaper Engine 本身就不存在**，没有对接对象。选项：a) 直接禁用入口；b) 未来用自己的 WebView 视频墙纸替代

### C2. 全桌面模式 — 建议：重做或砍掉
- `full-desktop-mode-runtime.js`：PowerShell 内嵌 C# P/Invoke（user32/kernel32 的 SetWindowLongPtr、WorkerW、SetParent），把窗口挂到桌面 WorkerW 层
- mac 无等价 API（GeekTool 那类方案体验差距大）。**建议砍掉**，或退化为"透明置底窗口"模式

### C3. 桌面图标互动层 — 建议：砍掉
- `desktop-native-icon-layer-runtime.js`、`desktop-icon-shape-runtime.js`：大量 user32/kernel32 DllImport + conhost.exe/powershell.exe 隐藏进程管道
- 纯 Windows 玩法，无 mac 对应物

### C4. 桌面歌词
- `main.js` 中 4 处 `hookWindowMessage`（win32 消息钩子做鼠标穿透/拖动），`:3639` 的鼠标轮询仅 win32
- mac 可用 Electron 的 `setIgnoreMouseEvents({forward: true})` + 置顶窗口实现 80% 体验。**中等工作量，值得做**

### C5. 桌面壁纸模式（自己的 MP4 壁纸）
- `wallpaper-mode-runtime.js`：WorkerW 注入（PowerShell + C#）
- mac 无桌面壁纸层 API。**砍掉**，或提供"浮动半透明窗"替代

## D. 打包与分发

| 项 | 现状 | mac 工作量 |
|---|---|---|
| `package.json` build 配置 | 仅 `--win nsis`，含 rcedit 图标注入（`build/after-pack.js`）、`.ico`/安装位图 | 新增 `build:mac`（dmg），图标换 `.icns` |
| `installer.nsh` | NSIS 定制安装器 | mac 不需要，忽略 |
| 签名 | 未签名（SmartScreen 拦截的问题说明在 README） | mac 不签名会直接 Gatekeeper 拦死，**开发者账号 + 公证是刚性成本** |
| `start-mineradio.bat`、`quick-check.bat` | Windows 脚本 | 加等效 shell 脚本（ trivial） |

## 建议的移植顺序（最小可发布路径）

1. **第 1 步（1~2 天级）**：跑通 mac 开发环境——处理平台守卫、托盘/菜单、路径折叠、启动脚本，`npm start` 在 mac 起来，核心播放+歌词舞台可用。C1~C3、C5 功能入口隐藏。
2. **第 2 步（中等）**：mac 版桌面歌词（Electron 透明窗口方案）。
3. **第 3 步（分发）**：electron-builder 加 mac target + icns；决定是否买 Apple Developer 做签名公证（不公证用户要手动右键打开）。
4. **明确不做**：Wallpaper Engine、全桌面模式、图标互动层——这三个是"Windows 特色"，留着作平台差异化。

## 风险提示

- `desktop/main.js` 近 6000 行且全局状态多，改平台分支时容易牵连启动流程；建议每改一处守卫都回归测试启动。
- 原项目 GPL-3.0：你的 fork 衍生版也必须开源 GPL-3.0，改品牌可以，闭源不行。
- fork 后记得改 `package.json` 里更新机制的 `owner/repo`（目前指向 XxHuberrr/Mineradio），否则用户更新会拉回原版。
